## Build order

Build in this sequence. Each step depends on the one before.

### Step 1 — Knowledge base

Before any code, write and finalise your Markdown documents in `backend/knowledge_base/`. These are the source of truth. Everything downstream depends on their quality.

**Formatting rules for clean chunking:**

- Use `##` headings to divide logical sections — the chunker will split on these
- Keep sections between 150–400 words — too short loses context, too long dilutes relevance
- Be explicit: write "Tania built X using Y" not "built X using Y" — the persona is baked into the docs
- No tables in the knowledge base docs — they chunk badly; convert to prose or bullet lists
- End each document with a `## Summary` section — this gets retrieved often and should be dense

---

### Step 2 — Backend: ingest pipeline

`backend/ingest.py` is a one-off script. Run it locally whenever the knowledge base changes.

**What it does:**

1. Reads all `.md` files from `knowledge_base/`
2. Splits each into chunks (by heading + max token size)
3. Embeds each chunk using `sentence-transformers/all-MiniLM-L6-v2`
4. Stores embeddings + metadata in Chroma at `chroma_db/`

**Key decisions:**

- `chunk_size`: 400 tokens, `chunk_overlap`: 50 tokens — balances context vs retrieval precision
- Metadata stored per chunk: `source` (filename), `section` (heading), `doc_type` (cv / readme / narrative)
- `doc_type` tag enables filtered retrieval later (e.g. "only search CVs for this query")

---

### Step 3 — Backend: RAG pipeline

`backend/rag.py` is the core. It runs on every query.

**What it does:**

1. Embeds the incoming query using the same model as ingest
2. Queries Chroma for the top `k=5` most similar chunks
3. Filters out chunks below a similarity threshold of `0.72`
4. Builds a prompt from the retrieved chunks
5. Calls Claude API with the prompt
6. Returns the answer + source citations

**System prompt (baked into `rag.py`):**

```
You are a professional profile assistant for Tania, a London-based full-stack
developer. You answer questions about her background, skills, projects, and
experience using only the provided document excerpts.

Rules:
- Speak in third person: "Tania built..." not "I built..."
- Only use information present in the provided excerpts
- Cite your source at the end of each factual claim using [source: filename]
- If the excerpts do not contain enough information to answer, say:
  "That detail isn't in my current knowledge base — Tania can answer directly."
- Never invent skills, projects, or experiences
- Keep answers concise: 3–5 sentences unless a longer answer is clearly needed
```

---

### Step 4 — Backend: FastAPI app

`backend/main.py` exposes one endpoint:

```
POST /query
Body: { "question": string }
Response: { "answer": string, "sources": string[] }
```

Also expose:

```
GET /health
Response: { "status": "ok" }
```

The health endpoint is used by Railway to confirm the service is live, and by the Cloudflare Worker ping cron to keep it warm.

**CORS:** allow only your Cloudflare Worker's domain and `localhost:5173` for dev.

---

### Step 5 — Cloudflare Worker

`worker/index.js` sits between the frontend and the FastAPI backend.

**What it does:**

1. Receives the query from the frontend
2. Adds the Claude API key as a header (key stored in Worker env vars, never in frontend)
3. Enforces rate limiting: 15 requests per IP per hour via Cloudflare KV
4. Forwards the request to the FastAPI `/query` endpoint
5. Returns the response to the frontend

**Rate limit response (HTTP 429):**

```json
{ "error": "Too many requests. Please try again later." }
```

---

### Step 6 — Frontend

A single-page React app. No routing needed.

**Layout:**

```
┌─────────────────────────────────────────┐
│  whoistrs                    [gh link]  │
├─────────────────────────────────────────┤
│                                         │
│  [suggested question chips]             │
│                                         │
│  ┌─────────────────────────────────┐    │
│  │ answer text                     │    │
│  │ [source: cv-guardian.md]        │    │
│  └─────────────────────────────────┘    │
│                                         │
│  ┌──────────────────────────┐  [send]   │
│  │ Ask anything about Tania │           │
│  └──────────────────────────┘           │
└─────────────────────────────────────────┘
```

**Suggested questions (hardcoded, shown before first query):**

- "What projects has she shipped?"
- "What's her cybersecurity experience?"
- "How does she handle pressure?"
- "What stack does she work in?"
- "What did she do before tech?"

**Source pills:** each answer renders its `sources` array as small teal pills below the answer text, matching the mockup style.

## Environment variables

### backend `.env`

```
ANTHROPIC_API_KEY=sk-...
CHROMA_PATH=./chroma_db
EMBEDDING_MODEL=sentence-transformers/all-MiniLM-L6-v2
TOP_K=5
SIMILARITY_THRESHOLD=0.72
```

### worker env (set in Cloudflare dashboard, not in files)

```
ANTHROPIC_API_KEY=sk-...
BACKEND_URL=https://whoistrs-backend.railway.app
RATE_LIMIT_REQUESTS=15
RATE_LIMIT_WINDOW_SECONDS=3600
```

### frontend `.env`

```
VITE_WORKER_URL=https://whoistrs.your-subdomain.workers.dev
```

## Deployment

| Service | What deploys there | Free tier notes |
|---|---|---|
| Railway | FastAPI backend | $5/month hobby plan — no cold starts |
| Cloudflare Workers | Proxy + rate limiter | Free tier: 100k req/day |
| Netlify | React frontend | Free tier: sufficient |

**Deploy order:**

1. Deploy FastAPI to Railway — get the public URL
2. Set `BACKEND_URL` in Cloudflare Worker env — deploy Worker
3. Set `VITE_WORKER_URL` in Netlify env — deploy frontend

## Keep-warm strategy

Add a Cloudflare Worker cron trigger that pings `BACKEND_URL/health` every 10 minutes. This prevents Railway from sleeping the service between recruiter visits.

```toml
# wrangler.toml
[triggers]
crons = ["*/10 * * * *"]
```
